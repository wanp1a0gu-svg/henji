# 数据备份与恢复

站点的数据都在云端数据库（应用 `wbapp_9pvnTdP5dI1cB9PjsWg1Ou`），本地只跑服务端代码。
所以"备份" = 把云端的表导出来存到你自己的硬盘 / 网盘。

## 一、日常备份（你自己点，30 秒）

后台 → **备份** 标签 → 点「全量备份（JSON）」。

浏览器会下载一个 `traces-backup-YYYY-MM-DD.json`，里面是这些表：

| 表 | 内容 | 重要性 |
| --- | --- | --- |
| `payment_orders` | 订单（含收货地址、运单号、状态） | 最重要 |
| `wallet_accounts` | 钱包余额 | 最重要 |
| `wallet_transactions` | 钱包流水 | 最重要 |
| `readings` | 测算记录 | 中 |
| `product_stock` | 库存 | 低（可重建） |
| `withdrawals` | 提现申请 | 中 |
| `page_views` | 访问日志（最近 2 万条） | 低 |

也可以单表导出——比如只想存一份订单。

**节奏建议**：每次批量发货之后导一次；每月月初导一次归档。
文件丢到网盘或移动硬盘，**不要**放在项目目录里（那里会被 git 忽略，也不该进仓库）。

## 二、恢复

顺序很重要（有外键引用关系）：

```
1. wallet_accounts      ← 先恢复账户，余额以这里为准
2. wallet_transactions  ← 再恢复流水（有 ref_id 唯一索引，重复插入会被挡，安全）
3. payment_orders       ← 最后恢复订单（id 是自增，恢复时保留原 id）
```

恢复方式有两种：

**A. 用云控制台的 SQL 编辑器**（推荐，逐表执行）

把 JSON 里的数组转成 `insert into ... values ...`，注意：
- 金额字段是 **文本**（`"66.00"`），不要写成数字，否则会丢精度
- 时间字段保留原文（带时区）
- `payment_orders.id` 是自增列，恢复时必须显式给值并 `setval` 对齐序列

**B. 用管理接口逐条写回**（数据量小时）

## 三、我（搭子）能做的备份

如果哪天数据库连不上、或者你想让我做一次完整快照，跟我说一声，我可以直接从云端把
业务表拉下来写成 `db/backups/YYYY-MM-DD/backup.json`（今天的在 `db/backups/2026-10-29/`）。

⚠️ 这些文件含真实邮箱和金额，**不要提交进 git**，已在 `.gitignore` 里排除。

## 四、还没有的能力（说清楚免得误会）

- **没有自动定时备份**：云平台不给外部定时任务，得靠你点，或者我手动做
- **没有数据库结构版本管理**：表结构改动靠 `db/*.sql` 手工同步，改表结构时记得同步文件
- **没有异地容灾**：云端本身的可用性由平台负责，我们只能保证"有导出、能重建"
