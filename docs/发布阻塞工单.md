## 已排除的本地因素（供平台排查参考）

| 试验条件 | 结果 |
|---|---|
| 工作区根目录放置 `.wbapp_9pvnTdP5dI1cB9PjsWg1Ou.genie`，localDir 指向真实目录 `D:\网站\mingli-club` | 仍返回 `e167b317...` 沙箱域名，未更新原应用 |
| 同上，改从 `G:\网站\mingli-club`（映射盘）发布 | 新建 `wbapp_N2p95wo2CFZ7YtFNaorLVN` |
| 工作区仅保留该 genie 一份、项目目录也放一份，从 `D:\网站\mingli-club` 发布 | 仍返回 `e167b317...`，原应用未被触达 |
| 发布参数显式传 `appId=wbapp_9pvnTdP5dI1cB9PjsWg1Ou` | 被忽略，目标仍由目录决定 |
| 云服务 `activate(reuse, applicationId=wbapp_9pvn...)` | 返回 `reuse_not_found`，会话内仅见 `wbapp_N2p95wo2CFZ7YtFNaorLVN` |

补充观察：发布工具**只在新应用创建时**才写 `.wbapp_<appId>.genie`；对已有应用重复发布不会写。因此该文件是"创建标记"，不是"绑定输入"，本地无法通过它改变发布目标。

## 为什么必须保留原域名（代码证据）

`lib/cloud.ts` 中：

```ts
/**
 * publicConfig returned by the WorkBuddy Cloud Service activation
 * (application wbapp_9pvnTdP5dI1cB9PjsWg1Ou)
 * ... server enforces origin match.
 */
export const CLOUD_PUBLIC_CONFIG = {
  endpoint: "https://mingli-club.app.workbuddy.host",
  oauthRelayBaseUrl: "https://www.workbuddy.cn/v2/as/genie-baas/oauth",
  ...
}
```

云端按 **origin 精确匹配**，白名单就是老域名。换域名会导致登录、钱包、下单等云服务调用失效——所以"用新域名也一样"不成立。
